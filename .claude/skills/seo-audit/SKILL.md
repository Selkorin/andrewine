# Аудит SEO и ГЕО

## Запуск

```bash
cd /workspace/andrewine && npm run build
node .claude/skills/seo-audit/scripts/check-seo.mjs
```

Скрипт разбирает собранный `dist/` и данные статей, ничего не запускает в
браузере и работает без сети.

## Что проверяется и почему это важно именно здесь

**Уникальность title.** Две страницы с одинаковым или почти одинаковым
заголовком делят между собой сигналы — обе проседают. На этом сайте это
реальный риск: страницы выкупа `buy_*` и разделы журнала
`/articles/<категория>/` говорят про один и тот же напиток.

**Разведение интентов — правило, а не рекомендация.** Закреплённое
распределение:

| Тип страницы | Интент | Заголовок |
|---|---|---|
| `/buy_<напиток>/` | транзакционный | «Выкуп X в Москве — продать … дорого» |
| `/articles/<категория>/` | оценочный | «Оценка X: сколько стоит и как продать» |
| `/premium_alcohol/` | головной | «Скупка элитного алкоголя …» |
| статья | информационный | тема материала |

Раздел журнала НЕЛЬЗЯ переводить на «продать элитный X в Москве»: это ровно
тот запрос, который держит `buy_*`. Так теряются обе страницы, а покрытие
запросов не растёт.

**Длины.** title ≤ 65 знаков (Яндекс обрезает раньше Google),
description 120–175. Слишком короткий description поисковик перепишет сам.

**ГЕО.** Каждая статья и каждый раздел должны естественно упоминать Москву
или Россию — без этого гео-запросы не связываются с сайтом. Спам не нужен:
одного-двух упоминаний в FAQ или примечании достаточно.

**Целевой токен.** Позиционирование сайта — «принимаем в коллекцию элитный
алкоголь». Фраза «элитный алкоголь» должна встречаться в журнале
регулярно; когда-то её не было ни в одной статье, и журнал не помогал
коммерческим страницам.

**JSON-LD.** Каждая страница журнала несёт CollectionPage/Article, FAQPage,
BreadcrumbList и LocalBusiness. Скрипт парсит их и падает на битом JSON.

**Шаблон статьи.** 3 секции × 2 абзаца по 35–55 слов, чек-лист из 4 пунктов,
3 вопроса FAQ с ответами 25–45 слов. Разнобой в глубине материалов уже был
проблемой: первые шесть статей оказались вдвое тоньше остальных.

## Запреты в контенте (проверяются автоматически)

- конкретные цены, суммы, проценты — оценка индивидуальна, а чужие ценники
  публиковать нельзя;
- обещания выкупа («мы купим», «гарантируем»);
- привязка к датам («в 2026 году») — заголовок устаревает;
- превосходные степени.

Формулировка везде одна: оценка **предварительная, по фотографиям**, итог —
**после очного осмотра**.

## Оптимизация под ИИ-ответы

Прямо влиять на генеративные ответы нельзя, и обещать позиции в них нельзя.
Работает только одно — делать текст **пригодным для извлечения**:

- **прямое определение** первым: «Коллекционный коньяк — это …». Фраза должна
  быть понятна вне контекста страницы;
- **факты списком**, а не прозой (`priceFactors` в данных категории);
- **вопрос-ответ**, где ответ начинается с сути, без разгона;
- те же факты продублированы в JSON-LD;
- `llms.txt` (генерируется из `src/pages/llms.txt.ts`) — карточка компании и
  карта разделов для ИИ-краулеров. При добавлении раздела он обновляется сам.

## Проверка картинок

Только реальные файлы Wikimedia Commons с подтверждённым автором и лицензией.
Прямой доступ к commons.wikimedia.org из песочницы закрыт прокси (403) —
проверять существование файла поиском по точному имени. Имена не выдумывать;
если автора подтвердить не удалось — указывать лицензию без имени, а не
угадывать.
